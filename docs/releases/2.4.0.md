# CLIMS 2.4.0

- Adds reports and analytics: trends per day, week or month (`GET /reports/trends`) and hotspot coverage by region, district, venue type and dispenser condition (`GET /reports/hotspots`). Every dashboard has filters and a PDF download.
- Makes MOH a read-only overseer with access to every store's orders and every district's hotspots. NMS and JMS can read reports.
- Field roles (VHT, hotspot manager, delivery agent) now use only the mobile app. Web sign-in refuses them, and the web `/vht` workspace and Submit hotspot form are removed.
- Fixes from a platform audit:
  - Non-admins can no longer grant the admin role or edit, lock or reset an admin account. Identity-sync revocations are audited.
  - Inventory reports `incoming` stock, uses the Kampala day for periods, and no longer deadlocks on concurrent batch edits.
  - Report periods no longer shift by 3 hours, stock held only in transit is listed, and bad requests return the right status codes.
  - The web clears its cache when the signed-in user changes and no longer signs people out on a two-tab token refresh.
  - The field app keeps queued sends through server errors and retries them, and sign-out gives up the push token.

## Upgrade from 2.3.0

Back up PostgreSQL before deploying. The backend applies migration 000039 at startup. It gives the `moh` role every read permission and removes `catalogue:manage` from it, so MOH users can no longer edit the catalogue.

There are no new production settings.
